# 环境发现与工作流路由

英文版本：[discovery-and-routing.md](discovery-and-routing.md)。

## 发现当前环境

连接硬件前确认：

- 仓库、板卡、MCU/内核和当前固件配置。
- 匹配的 ELF/AXF 与 map 文件，包括时间戳和构建身份。
- 探针类型、传输方式、唯一 ID/序列号，以及是否存在多个探针。
- 调试工具入口和版本。
- 支持的 target 名和所需器件包。
- 接线与目标能够支持的 SWD/JTAG 频率。
- 支持的复位方式，以及 NRST 是否物理连接。
- Keil、其他调试器或下载器是否已经占用探针。

如果项目提供 `agent/debug/` 文档和脚本，优先读取。项目脚本只能证明该项目的配置，
不能作为可移植默认值。

存在多个探针时不得自动选择。根据项目、当前硬件或用户信息确定目标 UID。

## 按任务路由

| 任务 | 主要工作流 |
| --- | --- |
| 编译/链接或检查构建错误 | Keil/构建工作流 |
| 烧录/下载固件 | 经授权的 Keil/下载器工作流 |
| 读取启动日志或协议数据 | 串口工作流 |
| 卡死、Fault、复位、CPU 状态 | 嵌入式调试工作流 |
| SPI/I2C/UART/PWM/复位时序 | 信号采集工作流 |
| 模拟完整性、振铃、电压、上升时间 | 示波器/电气工作流 |

只有已连接探针和所选 target 被支持时才使用 pyOCD。文档提到 ST-Link 或 J-Link，
并不能证明本地 pyOCD 支持它。把不受支持的探针路由到经过验证的厂商或项目工具。

## 停止并询问

出现以下情况时，在影响硬件状态前停止：

- 目标板、MCU、探针或 UID 不明确。
- 文档命令与当前工具或硬件冲突。
- 缺少所需 target/器件支持。
- 请求硬件复位但复位接线未知。
- 其他工具可能占用探针。
- 符号文件可能与运行固件不匹配。
- 用户可能正在保留故障现场或进行时序敏感实验。

只询问安全选择下一步所需的最少信息。
