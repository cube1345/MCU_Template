# 证据与故障分诊

英文版本：[evidence-and-triage.md](evidence-and-triage.md)。

## 从时间线开始

记录：

- 故障前发生了什么变化。
- 板卡是否依次到达复位、启动、调度器启动和应用心跳。
- 最后一条串口日志、断言或状态变化。
- 问题能否复现，以及触发条件。
- 复位是否只能暂时消除问题。
- 连接调试器是否改变症状。

确认符号文件和源码与正在运行的固件一致。

## 分类症状

### 无法启动或复位循环

检查复位原因、供电/复位行为、启动日志、向量/入口状态，以及固件映像是否匹配板卡。
如果复位原因很重要，应先保存当前证据，再考虑复位。

### 卡死或等待

短暂采集 PC、LR、SP、xPSR、BASEPRI 和 PRIMASK。使用匹配的 ELF/AXF/map
符号化 PC/LR，判断执行位置是正常代码、忙等、调度器空闲、锁等待、延时/tick 等待，
还是 Fault handler。

单次快照只能表示采样时的位置，不能直接证明根因。只在需要时重复采样或补充目标状态。

### Fault

采集核心寄存器、当前栈指针和异常栈帧、异常状态，以及当前架构支持的 Fault 状态
寄存器。复位前保留第一次 Fault 证据，并使用匹配符号文件解析地址。

### 外设或全局状态

读取前必须根据符号、map、SVD 或器件手册确认地址。注意读清除和带副作用的寄存器；
调试器读取并不一定在电气或语义上完全无影响。

### 探针冲突

检查 Keil Debug、其他 pyOCD/OpenOCD 进程、厂商下载器或 IDE 是否正在使用同一探针。
应退出或协调占用者，而不是无限重试。

### 时序或电气行为

软件状态无法区分假设时，请求针对性的逻辑分析仪或示波器采集。不能根据源码推断
实际总线时序。

## 组织结论

分三类报告：

1. **已观察事实**：直接日志、寄存器值、波形事件、退出状态。
2. **推断**：这些事实最支持的解释。
3. **未验证假设**：仍可能成立的替代解释，以及排除它们所需的证据。

最后给出能够区分剩余假设的最小下一步测试。
