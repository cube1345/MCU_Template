# 项目发现与执行前检查

英文版本：[project-discovery.md](project-discovery.md)。

运行 Keil 命令前使用本清单。目标仓库及其受版本控制的文档优先于本 Skill 的示例。

## 阅读项目本地规则

查找并读取最小相关集合：

1. 仓库的 Agent 索引或 `AGENTS.md`。
2. `agent/keil/` 文档和脚本。
3. 项目提供的 PowerShell 规则。
4. 目标 `.uvprojx`；烧录时还要检查 `.uvoptx` 配置。

不能因为脚本存在就推断它当前仍然有效。

## 构建预检

确认：

- Keil 可执行文件存在，通常为 `UV4.exe`。
- 目标 `.uvprojx` 存在。
- 工程包含多个 Target 时，选中的 Target 确实存在。
- 器件、编译器/工具链、Pack 和包含路径合适。
- 输出目录和输出名指向预期 AXF/HEX。
- 已知构建日志路径，并且不会与其他活动构建冲突。
- 命令没有依赖错误的当前工作目录。

如果已有旧产物，记录其时间戳和大小，以便发现“命令返回但没有刷新产物”的情况。

## 烧录预检

除构建检查外，还要确认：

- 用户明确要求或批准烧录。
- 已连接的板卡和 MCU 是本次目标。
- 调试探针/下载器与工程配置一致。
- Flash 算法与 MCU 和 Flash 容量布局一致。
- Flash 基地址与范围正确。
- 产物来自预期构建，而不是无关旧文件。
- 板卡供电和调试连接足够稳定。

如果不能从项目、日志、硬件连接或用户请求中安全确认某一项，在烧录前停止并询问
最少的缺失信息。

## 配置变化

如果工程、器件、输出路径、工具链、算法或探针发生变化：

1. 不要运行过期脚本。
2. 从当前项目文件识别真实配置。
3. 仅当修改属于本次任务范围时，更新或替换项目命令。
4. 执行前重新完成预检。
