# Keil uVision 工作流

英文版本：[workflows.md](workflows.md)。

## 动作选择

| 用户意图 | 动作 | 硬件影响 |
| --- | --- | --- |
| 构建、编译、检查错误、验证固件 | 构建 | 无 |
| 烧录、下载、给板卡编程 | 烧录 | 改写目标 Flash |
| 构建并烧录、编译并下载 | 先构建再烧录 | 构建后改写目标 Flash |
| 运行 | 检查项目文档 | 含义不明确，不能猜测 |

## 常见 UV4 命令形式

使用带引号的项目实际路径：

```text
"<UV4.exe>" -b "<project.uvprojx>" -j0 -o "<build-log>"
"<UV4.exe>" -f "<project.uvprojx>" -j0 -o "<flash-log>"
```

- `-b`：构建已配置的 Target。
- `-f`：执行工程配置的烧录/下载流程。
- `-j0`：请求使用可用的并行构建能力。
- `-o`：把 uVision 输出写入指定日志文件。

应结合已安装的 uVision 版本和项目脚本验证这些参数。不要复制无关项目的路径、
Target 或输出名。

## 构建

1. 执行前读取候选脚本。
2. 确认它只调用 UV4 `-b` 等构建行为，不包含 UV4 `-f`、调用烧录脚本或启动
   构建并烧录包装脚本。
3. 记录构建前产物状态。
4. 运行验证过的纯构建脚本或构建命令。
5. 立即保存退出码。
6. 要求构建日志存在。
7. 解析并报告错误和警告。
8. 确认预期产物存在；预期重建时还要确认产物已刷新。

不能把带警告的构建静默当成完全成功。它可能仍生成产物，但必须单独报告警告。

## 烧录

1. 完成烧录预检和授权门槛。
2. 确认目标产物存在，并记录其时间戳和大小。
3. 运行项目烧录脚本或经过验证的烧录命令。
4. 立即保存退出码。
5. 要求烧录日志存在。
6. 检查擦除、编程和校验状态。

烧录成功不等于应用功能正常。

## 构建并烧录

将构建和烧录作为两个明确阶段执行：

```text
构建
  ├─ 失败、日志缺失、存在错误或产物无效 -> 停止
  └─ 产物验证通过 -> 烧录
       ├─ 失败 -> 报告并保留日志
       └─ 编程验证通过 -> 报告硬件写入完成
```

新构建失败后，即使旧 AXF 仍然存在，也绝不能继续烧录。

## 脚本命名

名为 `run_keil.bat` 的项目脚本可能表示构建并烧录，而不是交互式调试/运行会话。
使用前读取其实现并描述真实行为。如果脚本包含烧录，则禁止用于仅构建请求。
