# 烧录安全

英文版本：[flashing-safety.md](flashing-safety.md)。

烧录会擦除或改写已连接硬件的非易失存储器。操作必须限制在用户授权的具体板卡和
固件范围内。

## 授权门槛

用户明确要求烧录、下载、编程或执行有文档说明的构建并烧录流程时，才能继续。不能从
构建、验证、测试编译、查看日志或检查代码等请求中推断烧录权限。

如果名为 `run` 的项目脚本实际会烧录，应说明这一行为；除非用户请求已经明确包含烧录，
否则必须获得授权。

## 目标门槛

执行前确认：

- 目标仓库和 `.uvprojx`。
- 目标 Target、MCU 和已连接板卡。
- 预期固件产物及其新鲜度。
- 探针/下载器类型。
- Flash 算法和地址范围。

如果无法安全地区分当前连接目标与其他板卡，或者配置的算法与 MCU 不一致，立即停止。

## 失败处理

- 构建失败或未验证时禁止烧录。
- 禁止静默替换为旧产物。
- 保留并报告相关日志。
- 未诊断失败原因前，不要反复重试硬件写入。
- 除非另有明确授权，不得从烧录扩大到复位、全片擦除、选项字节修改或调试配置修改。

## 烧录后结论

区分以下结果层级：

1. 工具连接到目标。
2. 擦除/编程完成。
3. 校验通过。
4. 目标启动。
5. 固件行为经过功能验证。

只能声称证据实际支持的最高层级。
