# DS2026 钢球视觉串口协议说明

本文用于说明 Jetson 视觉程序与下位机之间的串口数据关系。

## 1. 基本串口配置

- 波特率：`115200`
- TX 与 RX 默认使用同一个串口：`/dev/ttyACM0`
- 多字节数据顺序：高字节在前（大端序）
- 坐标原点：水管中央加粗的 `0 cm` 刻度
- 坐标方向：画面左侧为负，画面右侧为正

示意：

```text
水管左端                 中心                  水管右端
  -12 cm                  0 cm                  +12 cm
     <---------------------|--------------------->
          X < 0                              X > 0
```

## 2. Jetson 发给下位机的钢球数据帧

### 2.1 固定帧格式

每帧固定为6字节：

```text
AA | X_H | X_L | V | A | FF
```

| 字节序号 | 名称 | 含义 |
|---|---|---|
| 0 | `0xAA` | 帧头 |
| 1 | `X_H` | X坐标高字节 |
| 2 | `X_L` | X坐标低字节 |
| 3 | `V` | 速度量 |
| 4 | `A` | 加速度量 |
| 5 | `0xFF` | 帧尾 |

下位机检测到 `0xAA` 后，应固定读取后续5字节，再检查第6字节是否为
`0xFF`。不能在中途看到 `0xFF` 就提前结束，因为负数数据本身也可能等于
`0xFF`。

### 2.2 X坐标

X为有符号16位整数，采用二进制补码和大端序：

```text
X = 小球中心X像素 - 水管0cm刻度X像素
```

当前程序将X限制在：

```text
-320 ～ +320 px
```

含义：

- `X = 0`：钢球中心与水管0cm刻度重合。
- `X > 0`：钢球位于水管中心右侧。
- `X < 0`：钢球位于水管中心左侧。
- X绝对值越大：钢球距离中心越远。

编码示例：

| 钢球位置 | X十进制 | X编码 |
|---|---:|---|
| 中心 | 0 | `00 00` |
| 中心右侧100像素 | +100 | `00 64` |
| 中心左侧100像素 | -100 | `FF 9C` |
| 最右限制 | +320 | `01 40` |
| 最左限制 | -320 | `FE C0` |

下位机C语言解码示例：

```c
uint16_t x_raw = ((uint16_t)rx[1] << 8) | rx[2];
int16_t x = (int16_t)x_raw;
```

### 2.3 速度量V

V为相邻两次有效检测的X像素差：

```text
V[n] = X[n] - X[n-1]
```

单位暂定为：

```text
像素/帧
```

V采用有符号8位整数、二进制补码：

```text
-128 ～ +127
```

程序会对超出范围的数据进行限幅。

方向含义：

- `V > 0`：钢球正在向右运动。
- `V < 0`：钢球正在向左运动。
- `V = 0`：本帧与上一帧位置相同或变化不足1像素。

下位机解码：

```c
int8_t velocity = (int8_t)rx[3];
```

### 2.4 加速度量A

A为相邻两帧速度量的差：

```text
A[n] = V[n] - V[n-1]
```

单位暂定为：

```text
像素/帧²
```

A采用有符号8位整数、二进制补码，范围为 `-128～+127`，超出时限幅。

方向含义：

- `A > 0`：速度变化趋势偏向右侧。
- `A < 0`：速度变化趋势偏向左侧。
- `A = 0`：相邻两帧速度量没有变化。

下位机解码：

```c
int8_t acceleration = (int8_t)rx[4];
```

### 2.5 连续运动示例

假设连续三帧检测到：

```text
X: +10 → +15 → +18
```

发送结果：

```text
第1帧：AA 00 0A 00 00 FF
第2帧：AA 00 0F 05 05 FF
第3帧：AA 00 12 03 FE FF
```

解释：

```text
第1帧：首次有效检测，V=0，A=0
第2帧：V=15-10=+5，A=5-0=+5
第3帧：V=18-15=+3，A=3-5=-2，-2编码为FE
```

如果X逐渐减小，则钢球向左运动，V会变成负数。

### 2.6 首帧、漏检与通信看门狗

摄像头刚启动或钢球重新被检测到的第一帧：

```text
V = 0
A = 0
```

模型没有检测到钢球时，Jetson当前不会发送钢球数据帧，并会清空速度历史。
因此下位机必须设置接收超时保护。

建议：

```text
连续150～200 ms没有收到完整钢球帧 → 判定视觉数据失效
```

失效后应停止使用旧坐标，并进入预先约定的安全控制状态。

## 3. 下位机发给Jetson的任务帧

任务帧固定为4字节：

```text
AA | DATA_1 | DATA_2 | FF
```

### 3.1 模式1：找中心

```text
AA 00 00 FF
```

目标为水管中心 `0 cm`。

### 3.2 模式2：O到+5再到-5

```text
AA 55 00 FF
```

目标顺序为：

```text
0 cm → +5 cm → -5 cm
```

### 3.3 模式3：任意目标位置

```text
AA | 整数位 | 小数位 | FF
```

- 整数位：有符号8位二进制补码，允许 `-12～+12`。
- 小数位：十进制一位，允许 `0～9`。

示例：

```text
AA 05 03 FF → +5.3 cm
AA FB 03 FF → -5.3 cm
AA 07 00 FF → +7.0 cm
```

注意：当前格式不能区分 `+0.5 cm` 和 `-0.5 cm`，也不能把模式3的
`0.0 cm` 与模式1区分开。比赛联调阶段应避免发送这些有歧义的数据。

## 4. 三种模式与钢球上行数据的关系

无论当前处于哪个模式，Jetson发给下位机的X始终表示：

```text
钢球相对水管0cm刻度的实际像素坐标
```

它不是“目标位置”，也不是“目标误差”。

下位机应按照当前任务目标自行计算：

```text
控制误差 = 实际位置 - 目标位置
```

Jetson内部也会根据标定结果把像素换算为厘米，用于判断：

- 是否进入允许误差范围；
- 在目标点连续停留了多长时间；
- 模式2是否应从0切换到+5，再从+5切换到-5；
- 任务是否完成或超时。

## 5. 当前必须由双方确认的控制边界

现有Jetson上行帧只包含：

```text
实际X、V、A
```

没有包含：

```text
当前目标、模式2步骤、完成标志、超时标志
```

因此下位机无法直接知道Jetson内部模式2何时切换了目标。正式联调前必须在
以下两种方案中选定一种：

1. 下位机负责模式2的 `0→+5→-5` 状态机，Jetson只发送实际测量值；
2. Jetson负责状态机，之后另行增加“当前目标/步骤/完成状态”发送帧。

在没有增加新上行帧之前，建议采用方案1，由下位机负责闭环控制和模式2步骤
切换，Jetson状态机用于视觉侧监测和比赛结果判断。

## 6. 下位机接收流程建议

```text
等待0xAA
  ↓
固定读取剩余5字节
  ↓
检查rx[5]是否为0xFF
  ↓
按int16大端序解析X
  ↓
按int8解析V和A
  ↓
更新最后有效帧时间
  ↓
超过150～200ms未更新则进入安全状态
```
